# Domain docs

Misaka uses one glossary at `CONTEXT.md` and keeps architecture decision
records (ADRs) in `docs/adr/`.

Before exploring an area, read the root glossary and any ADRs relevant to
the work. If either is absent, proceed silently. The `domain-modeling`
skill creates these documents as terms and decisions are settled.

Use the glossary’s terms in issues, proposals, code, and tests. If a
needed concept has no established term, flag the gap for `domain-modeling`.

If a proposal conflicts with an ADR, cite the decision and explain why
it warrants reconsideration.
